# Biomes You'll Go（1.12.2 Legacy Edition）

日期：2026-10-18

## 版本

1.12.2 对应的是 **Oh The Biomes You'll Go: Legacy Edition**，即 BYG 的 Java 重写版，
不是现代版本 Oh The Biomes You'll Go。

- CurseForge 项目：`oh-the-biomes-youll-go-legacy-edition`（项目 ID 1564178）
- 文件：`OhTheBiomesYoullGo-1.0.1.jar`（文件 ID 9022845）
- modid：`byg`
- 版本：1.0.1，Minecraft 1.12.2 Forge

jar 已放入开发实例和专用服务器测试实例的 `mods/`。

## 配置

`config/OhTheBiomesYoullGo.cfg` 使用默认设置：

- 76 个 BYG 生物群系全部启用；
- `globalBiomeWeightMultiplier=1.0`；
- BYG 生物群系加入 Forge 的生物生成列表。

如需减少 BYG 生物群系占比，可调整 `globalBiomeWeightMultiplier` 或
`biomeWeightOverrides`。内容开关（木材、矿物、装备等）默认全开。

## 兼容性

专用服务器已启动到 `Done`，没有 BYG 相关的异常。日志中的
`Registry Biome: Object did not get ID it asked for` 是 RoughlyEnoughIDs 重新分配
ID 的正常提示，不是崩溃。

## 与 GT 矿脉的衔接

BYG 的特殊岩石（`rocky_stone`、`scoria`、`sepinite`、`soapstone`、`sodalite`）原本不在
GT 的 `StoneType` 表里，GT 矿脉在这些生物群系会直接跳过。`MinespaceBygStones` 在 GT
preInit 中注册了 5 个对应石种（ID 40–44），所以新生成的区块里 GT 矿脉可以正常替换
这些岩石。

另外，Gregicality 勘探仪原来会把同一方块的所有矿物词典别名都加一遍，列表里因此出现
两条“漂白土矿石”/“海绿石矿砂矿石”。`MixinProspectingMapMeta` 现在为每个方块选择
最短的 `ore*` 名称，只添加一次。勘探仪仍然是逐方块扫描，混合矿脉里的伴生矿和陨石里的
孤立矿会显示成散点；现在只有 3×3×3 范围内至少有 5 个相同方块的矿簇才会进入地图和
列表，孤立的赛特斯石英、塔姆雷特等“零碎”矿不再刷屏。真正的 GT 矿脉矿块密集，不受影响。

这两项只影响新生成的区块；已经生成的旧区块不会补写矿脉。

## 汉化

BYG Legacy Edition 自带 `en_us`、`fr_fr`、`hu_hu`，没有 `zh_cn`；I18nUpdateMod 资源包里的
BYG 汉化是旧版 MCreator BYG 的无下划线 key，和 Legacy Edition 的 key 只有 24 条重合。

现在 `resourcepacks/minespace-lang/assets/byg/lang/zh_cn.lang` 包含 Legacy Edition 的
全部 925 个 key：旧翻译按 key 归一化复用，木材/石材/装备按词根组合补齐，工具提示和进度
单独翻译。`tools/localize-byg.py` 是生成该文件的脚本。

BYG 的生物群系名字是 `new BiomeProperties("Allium Fields")` 这样的硬编码字符串，lang
文件够不到；`MixinBiomeName` 在 `Biome.getBiomeName` 返回时按 `byg:` 注册名查
`MinespaceBygNames`，覆盖 76 个群系名。注册名和世界数据不变。

## 矿物词典

BYG 自己手写了一些 `logWood`/`plankWood`/`slabWood`/`stairWood`/`fenceWood` 等条目，
但漏了若干变体，特殊石头也只有 `rocky_stone` 是 `stone`、`scoria`/`soapstone` 是
`cobblestone`。`MinespaceBygOreDictionary` 在 `postInit` 按注册名补齐并去重：

| 词典名 | BYG 条目数 |
| --- | ---: |
| `logWood` | 110 |
| `plankWood` | 27 |
| `slabWood` | 27 |
| `stairWood` | 27 |
| `fenceWood` | 55 |
| `fenceGateWood` | 27 |
| `doorWood` | 26 |
| `treeLeaves` | 63 |
| `treeSapling` | 46 |
| `stone` | 13 |
| `cobblestone` | 2 |
| `stoneBrick` | 3 |
| `stoneStairs` | 5 |
| `stoneWall` | 5 |

这样 GT、Forestry 和其他按标准矿物词典匹配的木材/石头配方都能接受 BYG 的对应方块。

## 林业自动农场

林业的 Arboretum 不读取 `treeSapling` 矿物词典，而是只种自己的 `farmArboreal`
farmable 列表。`MinespaceForestryBygFarm` 在 `postInit` 把 46 个 BYG 树苗逐个包装成
`FarmableSapling`，注册到 `FarmRegistry.getInstance().registerFarmables("farmArboreal", ...)`。
专用服务器日志确认：

```text
Forestry arboretum: registered 46 BYG saplings as plantable germlings
```

已经放置的旧 Arboretum 可能在创建时缓存了农场列表；如果新树苗不出现，拆掉重放或重新
设置电路。手动/管理农场的电路要选对应的 BYG 树苗，自动农场才会种它。

## 矿石的化学成分与 GT 科技线

BYG 的四种命名矿石不再只是“奇幻宝石”，`MinespaceBygMaterials` 在 GT 材料表里给出了
可计算的成分，GT 自动生成对应的离心/电解分离配方：

| 矿石 | 化学成分 | GT 处理 | 科技线用途 |
| --- | --- | --- | --- |
| 卡塞矿石 | Ni₁₀Cr₄Co₃Mo₂W₁ 天然耐热合金 | 离心 → Ni/Cr/Co/Mo/W | EV 高温合金，用于 EV 涡轮转子 |
| 拉萨利姆矿石 | (Ce,La,Nd)CO₃F 混合稀土氟碳酸盐 | 电解 → Ce/La/Nd/C + O/F | EV 光学传感器/发射器（稀土光学） |
| 帕德莱特矿石 | Be₃Al₂Si₆O₁₈ 绿柱石 | 电解 → Be/Al/Si + O | 铍/铝轻量化结构，补 GT 铍链 |
| 塔姆雷特矿石 | TiV₂O₆ 钒钛酸盐 | 电解 → Ti/V + O | HV 钛/钒合金，补 GT 钛钒链 |
| 方钠石 | Na₈Al₆Si₆O₂₄Cl₂ | GT 现有方钠石链 | MV 铝/钠/硅/氯来源 |

BYG 矿石方块先进入 GT 研磨机，产出对应材料粉和伴生矿粉；随后由 GT 的离心机/电解机
按成分拆分。普通挖掘掉落的 BYG 宝石也能直接研磨成 1 份材料粉，避免没有精准采集时
宝石无法进入 GT 链。卡塞粉再经合金炉回到卡塞锭。拉萨利姆板用于 EV 传感器/发射器；
卡塞板用于 EV 涡轮转子。其余元素粉直接接入 GT 已有的铍、钛、钒、铝、钠和稀土链。

BYG 自己生成的宝石/锭物品仍然存在，和新的 GT 材料物品同名；现在通过下面的双向
1:1 转换让两套物品可以互换，不再需要玩家猜某个配方只接受哪一套。

## 工具 GT 化与物品转换

四种材料都设置了 GT 工具属性（耐久、挖掘速度、攻击力），GT/Gregicality 会生成对应的
GT 镐、锹、剑、斧、锄配方（工具头 + 木柄）。BYG 自制工具的配方由
`scripts/byg_gt_tools.zs` 移除。盔甲保留 BYG 的物品，但改用对应的 GT 板制作
（头盔 5 板、胸甲 8 板、护腿 7 板、靴子 4 板），不再用原始 BYG 宝石。

BYG 原来的“9 宝石/锭 ↔ 块”工作台配方也已移除；块的压缩/解压交给 GT 的
压缩机/打包机，工作台只保留 BYG 块与 GT 压缩块之间的 1:1 转换。

工作台提供双向 1:1 转换：

- `byg:kasai_ingot` ↔ `ingotKasai`
- `byg:latharium_gem` / `pendorite_gem` / `tamrelite_gem` ↔ 对应的 GT `gem`
- `byg:*_block` ↔ 对应的 GT 压缩块 `block*`

矿石方块仍然走 GT 研磨机 → 粉 → 离心/电解，不在工作台直接换宝石，避免绕过加工链。

## GT 矿脉融合

BYG 原生的四种矿石生成已关闭（`config/OhTheBiomesYoullGo.cfg` 中
`generateKasaiOre`、`generateLathariumOre`、`generatePendoriteOre`、`generateTamreliteOre`
均为 `false`），矿石方块和内容开关保留。四种矿石不再各开一条单矿脉，而是作为
伴生成分并入化学上对应的现有 GT 混合矿脉：

AE2 的小型赛特斯石英矿簇也已在 `config/AppliedEnergistics2/AppliedEnergistics2.cfg`
里关闭（`CertusQuartzWorldGen=false`）。赛特斯石英现在只来自 GT 的石英矿脉/冰壳晶体
矿脉，以及 AE2 陨石结构；不会再在主世界或行星上撒出一片零碎矿点。陨石生成保持开启，
因为 AE2 的四个初始压印模板仍然只能从陨石获得。

| BYG 矿石 | 并入的混合矿脉 | 矿脉高度 | BYG 矿权重占比 |
| --- | --- | --- | ---: |
| 卡塞 | 下界镍矿脉 | y 10–45 | 12 / 112 ≈ 10.7% |
| 拉萨利姆 | 主世界独居石矿脉 | y 20–40 | 12 / 112 ≈ 10.7% |
| 帕德莱特 | 主世界铍矿脉 | y 0–35 | 12 / 112 ≈ 10.7% |
| 塔姆雷特 | 主世界铝土矿脉、磁铁矿脉 | y 40+ / y 50+ | 6 / 114 ≈ 5.3%、6 / 106 ≈ 5.7% |

矿脉名称、维度和高度沿用宿主矿脉，只在其 `weight_random` 列表里增加一项
`block:byg:*_ore`，因此 JEI 里仍然显示“镍矿脉”“独居石矿脉”等原有混合矿脉，
不会出现“卡塞矿脉”这种单矿脉。高度也随宿主矿脉，而不是 BYG 原来的 y 1–34 /
5–20 / 5–15；这是为了贴合 GT 的地质分层。

填充器使用 `block:byg:kasai_ore` 这类写法，而不是 `ore:kasai`。GT 的 `ore:` 只解析
GT 自己注册的 `BlockOre`，用它就必须给四种材料加 `GENERATE_ORE`，等于再生成一套
GT 矿石方块；`block:` 直接把 BYG 原方块放进 GT 矿脉，JEI 矿脉页和勘探仪显示的也是
玩家实际挖到的方块。

`oreKasai`/`oreLatharium`/`orePendorite`/`oreTamrelite` 词典名在 `postInit` 注册，
不能提前到物品注册事件：GT 会把提前出现的 `ore<Material>` 当成普通矿石，自动加一条
500 tick / 5 EU、没有伴生输出的研磨配方，反而覆盖掉本模组的平衡配方。

专用服务器验证：开发实例仍为 128 条矿脉定义（没有新增独立矿脉文件），测试实例
仍为 254 条（其中保留了历史重复副本）。日志会输出
`BYG mixed vein: byg:kasai_ore appears in [...]` 等四条记录，确认四种矿都已进入
宿主混合矿脉。
已有区块不会补写矿脉，需要在新生成区块或新世界才能看到。

### 新世界 filler 空状态修复

BYG 的自定义石种注册进 GT 后，部分 GT 矿石没有为这些石种生成矿石变体。
`OreFilterEntry` 在遇到这种石种时会从 map 里取到 `null`，整段区块的矿脉生成
因此中断。`MixinGTOreFilterEntry` 现在会回退到该矿石的普通石种变体（或任意一个
非空变体），矿脉继续生成，不再丢弃区块。`soapstone` 和 `talc` 另外补上了
`GENERATE_ORE`，避免 `soapstone_vein` 的 filler 没有方块可用。

## 装饰块中文名去重

BYG 的装饰石料和 GT/其他模组的材料中文名有冲突，`zh_cn.lang` 已改成不会混淆的名字：

- `方钠石` → `碧纹岩`（BYG 装饰石，不是 GT 的 Sodalite 材料/方块）；
- `火山渣` → `熔孔岩`；
- `云母块` → `赛平岩`（BYG 的 sepinite 不是云母/Mica）；
- `皂石` → `滑腻岩`；
- `岩石` → `崎岖岩`；
- `泥巴` → `塘泥块`，`泥砖` → `塘泥砖`，`泥炭土` → `腐殖土`，`牧场草方块` → `腐殖草方块`；
- 彩色水晶块/水晶 → `彩晶块`/`彩晶`，避免和 AE2、Ender IO、Galaxy Space 的水晶重名。

## 注意事项

- 加生物群系模组前先备份世界；已有区块不会重新生成，BYG 群系只会出现在新生成的区块；
- 76 个群系会改变原先的生物群系分布，旧世界的群系边界可能看起来不连续；
- 如果客户端启动崩溃，优先看 `latest.log` 中是否出现 biome ID 或 BYG 相关的
  `MissingMapping`/`Exception`。
